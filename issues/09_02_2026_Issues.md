# QUALiHOME System Feedback — Issues & Suggestions
**Date:** September 2, 2026
**System:** QUALiHOME (Annregar Realty)

---

## ADMIN SIDE

### Bug Reports

#### Issue 1 — Delete Project Not Working
- The delete project function is **not working**.
- The confirmation dialog shows **"Delete undefined?"** instead of the actual project name — the project name is not being passed/resolved correctly to the modal.

#### Issue 2 — House Model Numbers Not Synced Across Roles
- House model count is **not consistent** across Admin, Agent, and Client views.
  - Admin side shows **8 models** created.
  - Client side only shows **6 models** — 2 are missing.
  - Agent side also shows only **1 model** in listings instead of all models.
- When switching qualification filters on the client side, the model order/display breaks — sometimes only 1 model shows instead of all of them. Expected behavior: all models should show, then be arranged/sorted by qualification status (Qualified → Conditionally Qualified → Not Qualified).

#### Issue 3 — Admin Model Detail View Missing Full Price Breakdown
- On the admin side, when viewing a model's detail, the **full price breakdown is not displayed**.

---

### Feature Requests / Improvements

#### FR-1 — Add New Project: Remove Location Fields
- When adding a new project, remove the Region / Province / City / Barangay input fields from the Project form.
- Suggestion: move those location fields to the **Add Subdivision** step instead, since that's the more logical place.

#### FR-2 — Real-Time UI Updates (No Page Refresh)
- When adding a new project, subdivision, or house model, the list should **update in real time** without requiring a full page refresh.

#### FR-3 — Model Listing: Reorder Subdivision Dropdown
- In the "Add Model Listing" form, move the **Subdivision dropdown** higher — it should appear right after the Model Name input field.

#### FR-4 — Address Fields: Combine into One
- Street, Block, and Lot No. are currently 3 separate fields.
- Request: **merge into a single address text field** since users just copy-paste the full address anyway.

#### FR-5 — Price Fields: Auto-Format with Comma Separators
- All monetary/pricing input fields (Total Selling Price, Reservation Fee, Downpayment, etc.) should **automatically insert commas every 3 digits** as the user types (e.g., `8,869,374.02`).
- Apply this formatting globally to any field that accepts a peso amount.

#### FR-6 — Unit ID: Switch to Manual Input
- The Unit ID field is currently auto-generated.
- Request: **make it a manual input** instead, since each house has a fixed, predetermined unit ID.

#### FR-7 — Peso Sign (₱) Display Fix
- Some fields/cards are showing **"?"** instead of the Peso sign (**₱**).
- Fix the character encoding / font support so ₱ renders correctly everywhere.

## CLIENT SIDE

### Bug Reports

#### Issue 1 — Model Listing Count Mismatch (see Admin Issue 2 above)
- Client dashboard shows fewer models than what exists in the system.
- Filter/qualification switching breaks the display order.

#### Issue 2 — Similarity Shows "High" Even With No Training Data
- The C5.0 AI engine shows **"High Similarity"** on a qualification result even when the **Training Data table is completely empty** (0 records).
- This is incorrect — if there is no training data to compare against, the similarity score should not return "High."
- Expected logic:
  | Condition | Similarity Label |
  |---|---|
  | No matching/similar records in training data | **Low** |
  | Somewhat close to existing buyer records | **Moderate** |
  | Strong match found in past qualifications | **High** |

### Feature Requests / Improvements

#### FR-1 — Rename "Score" to "Similarity"
- In the qualification results and assessment history table, rename the **"Score"** column/label to **"Similarity"**.
- The result values should be **Low / Moderate / High** (not a raw percentage).
- This has already been partially implemented (screenshot shows "Similarity: High") — ensure it is consistent everywhere, including the assessment history table header.

#### FR-2 — "High Similarity" Badge: Move to Top of Card
- On model listing cards, the **"High Similarity"** badge should be repositioned to the **top of the card** for better visibility.
