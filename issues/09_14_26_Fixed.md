**Verified:** `POST /forgot-password` (AJAX) → `200 {"ok":true,…}`; production-safe warning log fires without the token URL.

## Issue 4 — Pre-Qualification Assessment: No Dependents Field ✅ Fixed

**Root cause:** `RegistrationForm` captured dependents, but `QualifyForm` had no such field — `client/routes.py:131` reused stale `profile.dependents` on every re-assessment, so ML results driven by dependents were silently wrong.

**Backend:**
- `app/client/forms.py` — added `dependents = IntegerField("Number of Dependents", [Optional(), NumberRange(0–20)])` to `QualifyForm` (after `age`) and to legacy `Step2EmploymentForm`. `Optional` (not `InputRequired`) for backward compat with existing profiles.
- `app/client/routes.py::qualify()` — GET prefills `form.dependents` from profile; POST writes `profile.dependents = int(form.dependents.data or 0)` and passes the **fresh form value** to `_compute_result()`; added `"dependents"` to `step_fields` error routing.
- `app/client/routes.py::save_and_result()` — same fresh-value fix (reads `s2.get("dependents")`), plus comma-safe `Decimal(str(...))` for session values.
- `app/main/routes.py:754-761` — dashboard prefill now includes `qualify_form.dependents`.

**Frontend (`app/templates/dashboard/client.html:Step 2`):**
- New dependents input (`#qm-dependents`, min 0 max 20) after the Age column, matching existing input-group styling.
- Wired `qmValDependents()` (blank→valid-as-0, else 0–20), `input`/`blur` listeners, `qmTrackedFieldIds`, `qmValStep(2)`, `qmApplyServerErrors` map, `qmClearAllValidationUI`, restore/clear/init paths.

**Verified:** authenticated `POST /qualify` with `dependents:2` → `{"ok":true}`; DB shows `profile.dependents=2` with fresh `QualificationResult`. `pbDependentsChildren` (buyer-modal purchase snapshot) deliberately untouched — different entity.

## Issue 1 — Recommended Houses: Qualification Filter Bug ✅ Fixed

**Root cause:** three layers used three definitions of "qualified" — backend `matched_props` filtered by budget/model/`max_loanable` only **plus** `if not matched_props: matched_props = all_props` fallback (re-injected everything); Recommended template used binary `price <= max_loanable`; only Qualified-Homes/Browse used the correct per-term `required_monthly_income` check.

**Backend (`app/main/routes.py`):**
- New `_is_affordable_any_term(pricing, client_income)` helper (next to `_compute_property_pricing`): True if income ≥ required income on **any** of 5/10/15/20 yrs, counting both Qualified (`income >= req`) and Conditionally Qualified (`income >= req * 35/42`, thresholds read from `SystemConfig` with 35/42 fallback). Fail-open on missing pricing/income.
- `matched_props` block: comment updated, **`all_props` fallback deleted entirely** — empty Recommended now renders its empty state by design.
- Second-pass filter applied after `property_pricing_map` is built: `matched_props = [p … if _is_affordable_any_term(…)]` (skipped when no income on file).

**Frontend:**
- `client.html` Recommended loop: `{% set is_eligible = price <= max_loanable %}` replaced with `client_income` + `req_income_map` → `is_eligible_any_year` (mirrors the Qualified-Homes block), card wrapped in `{% if is_eligible %}`.
- `app/static/js/client_dashboard.js::applyHomeBadges`: Recommended grid now hides `.badge-not-qualified` cards (badges recomputed by `updateHomeCardBadge`) and toggles `#homeRecommendedEmpty` on visible count — previously it only counted.

**Not regressed:** Browse year-split view (3-tier sort/split) untouched and used as the reference implementation; `matched_count` badge updates naturally.

## Issue 3 — Number Inputs: Missing Comma Formatting ✅ Fixed

**Root cause:** `main.js:sqhBindNumericFormatting` is opt-in via `input[data-commas]` and was only applied to admin/agent fields — client assessment (`qm-gross/qm-debt/qm-bmin/qm-bmax`), buyer modal (`pbGrossIncome`, `type="number"`), and all four register money fields had no formatting; several validators/DTI meters used raw `parseFloat(value)` (`parseFloat("100,000") → 100`).

**Backend (comma-safe submit):**
- `app/client/forms.py`, `app/auth/forms.py` — `_strip_commas` filter on all 8 `DecimalField`s (gross/debt/budget_min/budget_max).
- ⚠️ **Correction found during implementation:** WTForms 3.2.2 runs field `filters` *after* `DecimalField.process_formdata`, so `filters` alone still rejects `100,000.00` (proven: `Not a valid decimal value`). Added raw-form pre-cleaning **before** form construction — `_strip_comma_fields()` helper in `client/routes.py::qualify()`, equivalent inline block in `auth/routes.py::register()`.

**Frontend:**
- `client.html`: `data-commas` + `inputmode="decimal"` on all four `qm-*` money inputs; `pbGrossIncome` `type="number"` → `type="text" data-commas inputmode="decimal"`; `sqhBindNumericFormatting(qmModal)` on modal show.
- `client.html` wizard JS: new `qmNum()` (comma-strip) used in `qmValGross`/`qmValDebt`/`qmUpdateDti`; `qmValHousing` already stripped.
- `register.html`: `data-commas` + `inputmode="decimal"` on gross/debt/budget_min/budget_max; new `gqNum()` used in `vGross`/`vDebt`/`vBudget`/`updateDti`.
- `main.js` (global via `base.html`) auto-binds all `data-commas` inputs; `qmNormalizeNumericInput` still strips before AJAX POST as defense-in-depth.

**Verified:** `100,000.00` / `42,145` / comma budgets validate and submit (`{"ok":true}`); DTI meters compute on stripped values.
